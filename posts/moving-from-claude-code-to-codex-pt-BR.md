# Do Claude Code ao Codex — trocar de ambiente para continuar mudando

## Levar para o Codex uma marca construída com Claude Code

Uma parte grande da MODAY foi construída com Claude Code.

Ajustes no tema da Shopify, integração com a Gelato, distribuição do blog em vários idiomas,
chatbot, ideias de melhoria a partir do GA4, artigos localizados.
Mesmo em partes técnicas que eu ainda não entendia completamente,
eu jogava o trabalho para o Claude Code, conferia o resultado e seguia em frente.

Eu já escrevi sobre como uso o Claude Code.
Não organizar demais. Delegar. Ir no fluxo.
Esse jeito combinou comigo e funcionou muito bem na fase de construção.

E mesmo assim, agora estou tentando mover o ambiente de trabalho da MODAY para o **Codex**.

Não porque o Claude Code foi ruim.
Na verdade, é quase o contrário.
O Claude Code foi bom o bastante para eu querer testar se ainda assim eu consigo sair dele.

## Não quero depender de um único ambiente

O principal motivo é este.
Quero continuar em um estado em que posso trocar.

O mundo das ferramentas de AI ainda está evoluindo rápido demais.
A melhor opção de algumas semanas atrás pode virar algo comum depois de uma única release.
Ontem uma ferramenta parecia claramente a mais forte.
Hoje outro ambiente pode combinar melhor com o trabalho que está na minha frente.

Nessa velocidade, depender profundamente de um único ambiente parece arriscado.
Claro que existe força em usar uma ferramenta a fundo.
Contexto do projeto, arquivos de configuração, workflows, hábitos.
Quanto mais isso se acumula, mais rápido o trabalho fica.

Mas, ao mesmo tempo, fica mais difícil se mover.

Se a MODAY vai ser uma marca movida por AI,
o jeito de operar também precisa mudar junto com as ferramentas.
Foi assim com Shopify, Gelato, Render e Make.com.
Usar o que faz sentido naquele momento. Reconstruir quando deixa de fazer sentido.

O ambiente de desenvolvimento com AI deve ser tratado do mesmo jeito.

## A fase de construção acabou; começou a fase de operação

Outro motivo é que a MODAY mudou de fase.

Antes do lançamento, era quase tudo construção.
Criar a loja. Colocar os produtos. Traduzir as páginas. Conectar o fluxo de pedidos.
Montar o pipeline de distribuição do blog. Colocar um chatbot.

Nessa fase, o Claude Code foi muito forte.
Ele escrevia código, lia arquivos, organizava a estrutura
e implementava o que fosse necessário.
Tinha muita força para levar as coisas até o ponto de "está funcionando".

Mas o trabalho daqui para frente é diferente.

Melhorias de UI.
Apresentação das páginas de produto.
Hero images para o blog.
Posts para redes sociais.
Conceitos de vídeos curtos.
Imagens de modelos.
Criativos capazes de parar alguém no feed sem parecer anúncio.

Daqui em diante, código sozinho não basta.
O peso vai para **visual, linguagem, imagens, contexto e gancho**.

Para esse tipo de trabalho, o Codex parece combinar melhor agora.
O Image 2.0, em especial, está gerando imagens com qualidade que eu realmente posso usar.
E no desenvolvimento, para o escopo atual, não estou sentindo falta de nada.
Então faz sentido testar o Codex como ambiente de operação para esta fase.

## O Claude Code foi realmente bom

Quero deixar isso claro.
Sair do Claude Code não significa diminuir o Claude Code.

Basicamente, ele fazia tudo.
Pelo menos no lançamento da MODAY, eu não teria chegado até aqui sem ele.

O `/workflows`, lançado recentemente, também é realmente muito bom.
É uma função de qualidade.
Definir um fluxo e torná-lo reutilizável é exatamente o que você quer
quando o projeto cresce e vários processos precisam rodar de forma estável.
Quando eu entrar de novo em uma fase de desenvolvimento maior, quero usar isso outra vez.

Então esta não é uma história de "me formar" no Claude Code.
Se eu precisar, volto.
Em uma fase de desenvolvimento maior, o Claude Code pode muito bem voltar a ser a melhor opção.

Mas a MODAY agora não é um projeto enorme de engenharia.
A primeira montanha da construção já passou.
O que eu preciso agora são pequenas melhorias e criativos diários para crescimento.

Para esse volume de trabalho, o plano MAX do Claude Code começou a parecer um pouco grande demais.
Já o plano PRO parecia chegar nos limites rápido demais.

O Codex fica em um ponto que parece mais justo.
Esse também é um motivo honesto.

## O ponto fraco eram imagens e criatividade

A área em que senti mais atrito com o Claude Code
foi imagem e trabalho criativo.

Código, operações com arquivos, organização de estrutura: forte.
Localização de artigos: também bem utilizável.
Mas o que a MODAY precisa agora não é só algo que funcione bem.
Precisa de coisas que façam alguém parar no primeiro olhar.

Hero images do blog.
A primeira imagem de um post social.
Imagens de modelos para vídeos curtos.
O visual das páginas de produto.

Parar alguém no meio do scroll exige um tipo de julgamento diferente de escrever código correto.
Cor, composição, olhar, estranhamento, densidade de informação.
Para testar essas coisas, o Codex agora parece mais fácil.

Em um artigo anterior, quando comecei a trabalhar em vídeos curtos,
pedi ao Codex para escrever o storyboard e usei o ChatGPT Image para criar imagens de modelos.
Foi ali que senti pela primeira vez que as ferramentas da OpenAI
poderiam combinar melhor com o trabalho de crescimento.

Agora estou apenas levando esse movimento um pouco mais adiante.

## Isto não é uma comparação de ferramentas

Se este artigo for lido como "Claude Code vs Codex", ele perde um pouco o ponto.

Não estou tentando decidir qual ferramenta é melhor em geral.
Estou testando qual combina melhor com a MODAY agora.

O Claude Code combinou com a fase de construção.
O Codex pode combinar com a fase de operação e crescimento.
Se o desenvolvimento ficar maior de novo, talvez eu volte para o Claude Code.
Se outro ambiente aparecer e fizer mais sentido, talvez eu vá para ele também.

Tudo bem.

A MODAY foi construída assim desde o começo.
Deixei o Claude escolher um serviço POD que eu não conhecia.
Construí algo com FastAPI e Render, depois removi.
Achei que tinha deixado o Render para trás, depois trouxe de volta para o chatbot.
O pipeline do blog passou de tradução por API para rewrite dentro do Claude Code.

Usar o que parece certo naquele momento.
Reconstruir quando deixa de parecer certo.

Esta troca é só mais uma versão disso.

## A mudança deixa de ser um evento especial

Se alguém perguntar o que essa migração significa para a MODAY,
sinceramente, nem acho que precise transformar isso em um grande marco.

Mudar enquanto avança é a filosofia padrão.

A loja não está pronta só porque existe.
Um artigo não está pronto só porque foi publicado.
Um vídeo não está resolvido só porque uma versão foi postada.
As ferramentas de AI, a divisão do trabalho e o modo de operar vão continuar mudando.

Na verdade, o perigo seria parar de mudar.
No momento em que eu penso "é assim que vamos fazer",
começo a ficar para trás em relação ao ambiente.

Então eu troco.
Testo.
Se não encaixar, volto.
Se funcionar, sigo.

Esse nível de leveza já basta.

## O próximo passo

Mudar para o Codex não termina nada magicamente.

O trabalho continua bem concreto.

Escrever o blog.
Criar a hero image.
Melhorar a página de produto.
Fazer posts para redes sociais.
Criar a próxima ideia de vídeo curto.
Ler logs do chatbot e GA4, depois transformar isso em melhorias.
Melhorar uma coisa por dia.

Nessa repetição, vou ver até onde o Codex consegue ir.

Se funcionar, a fase de operação da MODAY vai rodar principalmente pelo Codex.
Se não funcionar, eu mudo de novo.

O importante não é qual ferramenta eu uso.
É continuar capaz de trocar de ferramenta.

Se a MODAY é uma marca movida por AI,
o jeito como trabalho com AI também não deveria ficar fixo.

Até a próxima.
