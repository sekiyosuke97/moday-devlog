# De Claude Code a Codex — cambiar de entorno para que la marca siga cambiando

## Mover a Codex una marca construida con Claude Code

Una parte grande de MODAY se construyó con Claude Code.

Ajustes del tema de Shopify, integración con Gelato, distribución del blog en varios idiomas,
el chatbot, ideas de mejora a partir de GA4, artículos localizados.
Incluso en capas técnicas que yo todavía no entendía del todo,
le pasaba el trabajo a Claude Code, revisaba lo que salía y seguía avanzando.

Ya escribí sobre cómo uso Claude Code.
No ordenar demasiado. Delegar. Seguir el impulso.
Ese estilo me encajó, y funcionó muy bien durante la fase de construcción.

Y aun así, ahora estoy intentando mover el entorno de trabajo de MODAY a **Codex**.

No porque Claude Code haya sido malo.
Más bien al contrario.
Claude Code fue lo bastante bueno como para que quisiera probar si podía moverme igualmente.

## No quiero depender de un solo entorno

La razón principal es esta.
Quiero mantenerme en un estado en el que pueda cambiar.

El mundo de las herramientas de AI se mueve demasiado rápido.
La mejor opción de hace unas semanas puede volverse normal con una sola release.
Ayer un entorno podía parecer claramente el más fuerte.
Hoy otro puede encajar mejor con el trabajo que tengo delante.

Con esa velocidad, depender demasiado de un único entorno da un poco de vértigo.
Por supuesto, usar una herramienta a fondo tiene fuerza.
Contexto del proyecto, archivos de configuración, workflows, hábitos.
Cuanto más se acumula todo eso, más rápido se trabaja.

Pero también se vuelve más difícil moverse.

Si MODAY va a ser una marca impulsada por AI,
la forma de operar también tiene que poder cambiar con las herramientas.
Pasó con Shopify, Gelato, Render y Make.com.
Usar lo que encaja en ese momento. Rehacer cuando deja de encajar.

El entorno de desarrollo con AI debería tratarse igual.

## La fase de construcción terminó; empezó la fase de operación

Otra razón es que MODAY cambió de fase.

Antes del lanzamiento, casi todo era construir.
Crear la tienda. Subir productos. Traducir páginas. Conectar el flujo de pedidos.
Montar el pipeline de distribución del blog. Poner un chatbot.

En esa fase, Claude Code fue muy fuerte.
Escribía código, leía archivos, ordenaba la estructura
y seguía implementando lo que hiciera falta.
Tenía mucha fuerza para llevar las cosas a "ya funciona".

Pero el trabajo que viene ahora es distinto.

Mejoras de UI.
Cómo presentar las páginas de producto.
Hero images para el blog.
Posts para redes.
Conceptos para videos cortos.
Imágenes de modelos.
Creatividad capaz de detener a alguien en el feed sin parecer un anuncio.

A partir de aquí, el código no alcanza por sí solo.
El peso se mueve hacia **lo visual, el lenguaje, las imágenes, el contexto y el gancho**.

Para ese tipo de trabajo, Codex parece encajar mejor ahora mismo.
Image 2.0, en particular, está dando imágenes con una calidad que sí puedo usar.
Y en desarrollo, para el alcance actual, no siento que me falte nada.
Así que tiene sentido probarlo como entorno de operación para esta fase.

## Claude Code fue realmente bueno

Quiero dejar esto claro.
Moverme desde Claude Code no significa que quiera restarle mérito.

Básicamente pudo con todo.
Al menos para lanzar MODAY, no habría llegado hasta aquí sin Claude Code.

La función `/workflows`, lanzada hace poco, también es de muy buena calidad.
Es realmente buena.
Definir un flujo y hacerlo reutilizable es justo lo que se necesita
cuando el proyecto crece y hay que repetir procesos con estabilidad.
Si vuelvo a una fase de desarrollo más grande, me gustaría usarlo otra vez.

Así que esta no es una historia de "graduarme" de Claude Code.
Si lo necesito, vuelvo.
En una fase de desarrollo más grande, Claude Code puede volver a ser la mejor opción.

Pero ahora mismo MODAY no es un proyecto de ingeniería enorme.
La primera montaña de construcción ya quedó atrás.
Lo que necesito ahora son pequeñas mejoras y material creativo para crecer todos los días.

Para esa carga de trabajo, el plan MAX de Claude Code empezó a sentirse demasiado grande.
El plan PRO, en cambio, parecía llegar a los límites demasiado rápido.

Codex queda en un punto que se siente más justo.
Esa también es una razón honesta.

## El punto débil eran las imágenes y la creatividad

Donde más fricción sentí con Claude Code fue en imágenes y trabajo creativo.

Código, manejo de archivos, ordenar estructuras: fuerte.
Localización de artículos: también muy útil.
Pero lo que MODAY necesita ahora no es solo algo que funcione bien.
Necesita cosas que hagan que alguien se detenga al primer vistazo.

Hero images del blog.
La primera imagen de un post social.
Imágenes de modelos para videos cortos.
La forma en que se ve una página de producto.

Detener a alguien mientras hace scroll exige un juicio distinto al de escribir código correcto.
Color, composición, mirada, rareza, densidad de información.
En este momento, Codex se siente más fácil para probar esas cosas.

En un artículo anterior, cuando empecé a trabajar en videos cortos,
le pedí a Codex un storyboard y usé ChatGPT Image para crear imágenes de modelos.
Ahí sentí por primera vez que las herramientas de OpenAI podían encajar mejor
con el trabajo del lado de crecimiento.

Este movimiento es dar un paso más en esa dirección.

## Esto no es una comparación de herramientas

Si este artículo se lee como "Claude Code vs Codex", se pierde un poco el punto.

No estoy intentando decidir cuál es mejor en abstracto.
Estoy probando cuál encaja mejor con MODAY ahora.

Claude Code encajó con la fase de construcción.
Codex puede encajar con la fase de operación y crecimiento.
Si el desarrollo vuelve a hacerse más grande, quizá vuelva a Claude Code.
Si aparece otro entorno que encaja mejor, quizá me mueva allí.

Está bien que sea así.

MODAY se construyó así desde el principio.
Dejé que Claude eligiera un servicio POD que yo no conocía.
Construí algo con FastAPI y Render, y luego lo quité.
Pensé que había dejado Render, y después lo recuperé para el chatbot.
El pipeline del blog pasó de traducción por API a rewrite dentro de Claude Code.

Usar lo que parece correcto en ese momento.
Rehacer cuando deja de sentirse correcto.

Este cambio es solo otra versión de lo mismo.

## El cambio deja de ser un evento especial

Si alguien pregunta qué significa esta migración para MODAY,
honestamente no creo que haga falta convertirla en un gran hito.

Cambiar mientras avanzo es la filosofía por defecto.

La tienda no está terminada solo porque exista.
Un artículo no está terminado solo porque se publique.
Un video no está resuelto solo porque haya una versión online.
Las herramientas de AI, el reparto del trabajo y la forma de operar van a seguir cambiando.

De hecho, lo peligroso sería dejar de cambiar.
En el momento en que pienso "esta es la forma",
empiezo a quedarme atrás respecto al entorno.

Así que cambio.
Pruebo.
Si no encaja, vuelvo.
Si funciona, sigo.

Ese nivel de ligereza es suficiente.

## Lo siguiente

Moverme a Codex no termina nada mágicamente.

El trabajo sigue siendo bastante terrestre.

Escribir el blog.
Crear la hero image.
Mejorar la página de producto.
Hacer posts para redes.
Proponer la siguiente idea de video corto.
Leer logs del chatbot y GA4, y convertirlos en mejoras.
Mejorar una cosa cada día.

En esa repetición voy a ver hasta dónde puede llegar Codex.

Si funciona, la fase de operación de MODAY girará principalmente alrededor de Codex.
Si no funciona, volveré a cambiar.

Lo importante no es qué herramienta uso.
Es seguir pudiendo cambiar de herramienta.

Si MODAY es una marca impulsada por AI,
la forma en que trabajo con AI tampoco debería quedar fija.

Nos leemos en la próxima.
