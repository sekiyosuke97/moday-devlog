# De Claude Code a Codex — changer d'environnement pour rester capable de changer

## Passer dans Codex une marque construite avec Claude Code

Une grande partie de MODAY a été construite avec Claude Code.

Ajustements du theme Shopify, integration Gelato, distribution du blog en plusieurs langues,
chatbot, idees d'amelioration a partir de GA4, articles localises.
Meme sur des couches techniques que je ne comprenais pas encore completement,
je donnais le travail a Claude Code, je verifiais le resultat, puis j'avancais.

J'ai deja ecrit sur ma facon d'utiliser Claude Code.
Ne pas trop organiser. Deleguer. Suivre l'elan.
Ce style me correspondait, et il a tres bien fonctionne pendant la phase de construction.

Et pourtant, j'essaie maintenant de deplacer l'environnement de travail de MODAY vers **Codex**.

Pas parce que Claude Code etait mauvais.
C'est plutot l'inverse.
Claude Code etait suffisamment bon pour que j'aie envie de tester si je pouvais quand meme en sortir.

## Je ne veux pas dependre d'un seul environnement

La raison principale est la.
Je veux rester capable de changer.

L'ecosysteme des outils d'AI evolue encore beaucoup trop vite.
La meilleure option d'il y a quelques semaines peut devenir banale apres une seule release.
Hier, un outil pouvait sembler clairement le plus fort.
Aujourd'hui, un autre environnement peut mieux correspondre au travail du moment.

A cette vitesse, dependre trop profondement d'un seul environnement me semble risqué.
Bien sur, il y a une vraie force a utiliser un outil en profondeur.
Contexte projet, fichiers de configuration, workflows, habitudes.
Plus tout cela s'accumule, plus le travail devient rapide.

Mais en meme temps, il devient plus difficile de bouger.

Si MODAY doit etre une marque pilotee par l'AI,
sa facon de fonctionner doit pouvoir changer avec les outils.
C'etait pareil avec Shopify, Gelato, Render et Make.com.
Utiliser ce qui convient a ce moment-la. Reconstruire quand ca ne convient plus.

L'environnement de developpement AI doit etre traite de la meme maniere.

## La phase de construction est terminee, la phase d'exploitation commence

L'autre raison, c'est que MODAY a change de phase.

Avant le lancement, il fallait surtout construire.
Creer la boutique. Ajouter les produits. Traduire les pages. Connecter le flux de commandes.
Monter le pipeline de distribution du blog. Installer un chatbot.

Dans cette phase, Claude Code etait tres fort.
Il ecrivait du code, lisait les fichiers, organisait la structure
et implementait ce qui etait necessaire.
Il avait une vraie puissance pour amener les choses a l'etat "ca fonctionne".

Mais le travail qui arrive maintenant est different.

Ameliorations d'UI.
Presentation des pages produit.
Hero images pour les articles.
Posts sociaux.
Concepts de videos courtes.
Images de modeles.
Creatifs capables d'arreter quelqu'un dans un feed sans ressembler a une publicite.

A partir d'ici, le code seul ne suffit plus.
Le poids se deplace vers **le visuel, le langage, les images, le contexte et l'accroche**.

Pour ce type de travail, Codex me semble mieux correspondre.
Image 2.0, en particulier, produit des images d'une qualite que je peux vraiment utiliser.
Et cote developpement, pour ce que je fais maintenant, je ne ressens pas de vraie limite.
Cela vaut donc la peine de le tester comme environnement d'exploitation pour cette phase.

## Claude Code etait vraiment bon

Je veux le dire clairement.
Quitter Claude Code ne veut pas dire que je le critique.

Globalement, il savait tout faire.
Au moins pour lancer MODAY, je ne serais pas arrive jusque-la sans Claude Code.

La fonctionnalite `/workflows`, sortie recemment, est elle aussi vraiment de grande qualite.
Elle est tres bonne.
Definir un flux et le rendre reutilisable, c'est exactement ce qu'il faut
quand le projet grossit et que plusieurs processus doivent tourner de facon stable.
Si je reviens a une phase de developpement plus lourde, j'aurai envie de l'utiliser a nouveau.

Ce n'est donc pas une histoire de "finir avec Claude Code".
Si j'en ai besoin, j'y reviendrai.
Dans une phase de developpement plus importante, Claude Code peut redevenir le meilleur choix.

Mais MODAY, aujourd'hui, n'est pas un gros projet d'engineering.
La premiere montagne de construction est passee.
Ce dont j'ai besoin maintenant, ce sont de petites ameliorations et du contenu creatif pour la croissance, tous les jours.

Pour cette charge de travail, le plan MAX de Claude Code commencait a sembler un peu surdimensionne.
Le plan PRO, de son cote, donnait l'impression d'atteindre les limites trop vite.

Codex se place dans un entre-deux qui me semble juste.
C'est aussi une raison honnete.

## Le point faible, c'etait l'image et la creation

Le domaine ou j'ai senti le plus de friction avec Claude Code,
c'etait l'image et le travail creatif.

Code, operations sur les fichiers, rangement de structure : tres fort.
Localisation des articles : tres utilisable aussi.
Mais ce dont MODAY a besoin maintenant, ce n'est pas seulement de choses qui fonctionnent proprement.
Il faut des choses qui accrochent au premier regard.

Hero images de blog.
Premiere image d'un post social.
Images de modeles pour les videos courtes.
Aspect d'une page produit.

Arreter quelqu'un pendant qu'il scrolle demande un jugement different de celui necessaire pour ecrire du code correct.
Couleur, composition, regard, etrangete, densite d'information.
Pour tester tout cela, Codex me semble plus facile a utiliser maintenant.

Dans un article precedent, quand j'ai commence a travailler sur les videos courtes,
j'ai demande a Codex d'ecrire le storyboard et j'ai utilise ChatGPT Image pour creer des modeles.
C'est la que j'ai senti pour la premiere fois
que les outils OpenAI pouvaient mieux convenir au travail cote croissance.

Ce deplacement prolonge simplement ce mouvement.

## Ce n'est pas une comparaison d'outils

Si on lit cet article comme un "Claude Code vs Codex", on passe un peu a cote.

Je ne cherche pas a decider lequel est meilleur dans l'absolu.
Je teste seulement lequel convient a MODAY maintenant.

Claude Code convenait a la phase de construction.
Codex conviendra peut-etre a la phase d'exploitation et de croissance.
Si le developpement redevient plus important, je reviendrai peut-etre a Claude Code.
Si un autre environnement devient plus adapte, je bougerai peut-etre encore.

Ca me va tres bien.

MODAY a ete construit comme ca depuis le debut.
J'ai laisse Claude choisir un service POD que je ne connaissais pas.
J'ai construit quelque chose avec FastAPI et Render, puis je l'ai retire.
Je pensais avoir abandonne Render, puis je l'ai reutilise pour le chatbot.
Le pipeline de blog est passe d'une traduction par API a un rewrite dans Claude Code.

Utiliser ce qui semble juste a un moment donne.
Reconstruire quand ca ne semble plus juste.

Ce changement n'est qu'une nouvelle version de la meme logique.

## Le changement cesse d'etre un evenement special

Si on me demande ce que cette migration signifie pour MODAY,
honnetement, je ne pense meme pas qu'il faille en faire un grand moment.

Changer en avancant est la philosophie par defaut.

La boutique n'est pas terminee parce qu'elle existe.
Un article n'est pas termine parce qu'il est publie.
Une video n'est pas reglee parce qu'une version est en ligne.
Les outils d'AI, la repartition du travail et la facon d'operer continueront a changer.

Le vrai danger serait plutot de ne plus changer.
Au moment ou je me dis "c'est comme ca qu'on fait",
je commence a prendre du retard sur l'environnement.

Donc je change.
Je teste.
Si ca ne convient pas, je reviens.
Si ca fonctionne, je continue.

Cette legerete suffit.

## La suite

Passer a Codex ne termine rien par magie.

Le travail reste tres concret.

Ecrire le blog.
Creer la hero image.
Ameliorer la page produit.
Preparer des posts sociaux.
Trouver la prochaine idee de video courte.
Lire les logs du chatbot et GA4, puis transformer ca en ameliorations.
Ameliorer une chose par jour.

C'est dans cette repetition que je verrai jusqu'ou Codex peut aller.

Si ca fonctionne, la phase d'exploitation de MODAY tournera principalement avec Codex.
Si ca ne fonctionne pas, je changerai encore.

L'important n'est pas l'outil que j'utilise.
L'important est de rester capable de changer d'outil.

Si MODAY est une marque pilotee par l'AI,
ma facon de travailler avec l'AI ne doit pas etre figee non plus.

A la prochaine.
